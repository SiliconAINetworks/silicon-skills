# Honest UI

Users forgive a missing feature. They never forgive a fake one.

## Rules

- **No fake features.** A button that does nothing, a chart filled with invented numbers, a "live" badge on static data: remove it or label it honestly ("coming soon", "demo data", "example").
- **Real numbers or no numbers.** Never show placeholder statistics, testimonials, user counts or prices that are not real. If data is missing, show an empty state that explains why and what to do.
- **Separate real from test.** Real money and test money, live data and sample data, production and sandbox are always visibly separated and never added together.
- **Errors say what happened and what to do.** "Something went wrong" is not a message. "The exchange rejected the key – check that it has trading permission" is.
- **No silent failures.** If a background job, sync or payment fails, the user sees it.
- **Name the limits.** If a plan, a free tier or a time window restricts something, say so where it matters, before the user hits the wall.

## Wording

- Plain language over jargon. Short sentences.
- Never promise outcomes you cannot guarantee (profits, security, "100%").
- Describe what the product *does*, not what it *is like*.

## Check before shipping

Go through every number, badge and status on the screen and ask: where does this come from, and is it true right now? If you cannot answer, it does not ship.
